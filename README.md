# Учёт оборудования котельных

Информационная система учёта оборудования котельных: объекты (котельные), оборудование с периодическими задачами технического обслуживания, предупреждения о просрочках, журнал работ, электронный паспорт объекта с PDF-экспортом, QR-коды на оборудование, автоматическое формирование заявок и график ТО.

## Технологии

- Laravel 13 + PHP 8.5
- Filament 5 (панель администратора)
- PostgreSQL 18
- barryvdh/laravel-dompdf (PDF-паспорт, DejaVu Sans для кириллицы)
- chillerlan/php-qrcode (SVG/PNG-коды, чистый PHP без GD)

## Требования

- PHP >= 8.5 с расширениями `pdo_pgsql`, `mbstring`, `xml`, `curl`, `zlib`
- Composer 2
- PostgreSQL 18
- Node.js >= 20 (для сборки ассетов)

## Установка

```bash
composer install
npm install
npm run build

cp .env.example .env
php artisan key:generate
```

В `.env` настройте подключение к PostgreSQL. Пример для доступа через unix-сокет:

```
DB_CONNECTION=pgsql
DB_HOST=/var/run/postgresql
DB_PORT=5432
DB_DATABASE=uchet_oborud
DB_USERNAME=denis
DB_PASSWORD=
```

Затем:

```bash
php artisan migrate
php artisan db:seed
php artisan storage:link
php artisan serve
```

Для загрузки больших файлов (схемы, фото > 2 МБ) запускайте dev-сервер через обёртку, которая поднимает лимиты PHP (`upload_max_filesize=64M`, `post_max_size=75M`):

```bash
./serve.sh
```

## Cron / планировщик

Автогенерация плановых заявок выполняется ежедневно в 06:00. Добавьте в cron:

```
* * * * * cd /путь/к/проекту && php artisan schedule:run >> /dev/null 2>&1
```

Либо запускайте вручную:

```bash
php artisan maintenance:generate-orders          # создать заявки
php artisan maintenance:generate-orders --dry-run # предпросмотр без записи
```

## Конфигурация интервалов

`config/maintenance.php`:

| Параметр | Значение | Описание |
|---|---|---|
| `due_soon_days` | 30 | За сколько дней до срока задача считается «скоро» |
| `work_order_lead_days` | 30 | За сколько дней до срока создаётся автозаявка |
| `work_order_duration_days` | 7 | Длительность запланированной заявки |

## Разделы панели

- **Дашборд** — сводные метрики, таблица «Требуют внимания», графики заявок/поломок/состава.
- **Объекты** — список котельных; страница просмотра = электронный паспорт (виджеты + PDF-экспорт, вкладки с оборудованием, заявками, историей работ). Общая схема котельной (JPG) загружается в форме объекта и открывается в паспорте в интерактивном режиме: масштабирование колёсиком мыши, перемещение перетаскиванием (Leaflet).
- **Оборудование** — карточки с фото, QR-кодом, статусом и сроками; QR-код ведёт на страницу оборудования в панели.
- **Заявки** — ручные и автогенерируемые; действия «Начать», «Выполнить», «Отменить».
- **Журнал работ** — история: ТО, ремонты, поломки, поверки; запись продвигает срок задачи.
- **Планирование ТО** — календарь месяца с задачами и заявками.

## Структура данных

- `facilities` — котельные (объекты). Модель `Facility` (не `Object` — зарезервировано в PHP).
- `equipment` — оборудование: серийный/инвентарный номер, тип, статус, дата установки, фото (JSON), QR.
- `service_tasks` — периодические задачи ТО: тип, период (дни/месяцы/годы), дата последнего выполнения → срок = дата + период.
- `work_orders` — заявки: тип, статус, приоритет, плановая дата, признак автогенерации.
- `work_journal_entries` — журнал работ: категория, дата, исполнитель, описание; связь с задачей и заявкой.

Сроки считаются на стороне БД (raw SQL) через `Equipment::nextDueExpression()` — единая формула для списков, виджетов и календаря.
